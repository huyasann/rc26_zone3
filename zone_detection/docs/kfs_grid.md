# KFS Grid — 九宫格颜色检测详细文档

> 节点: `kfs_grid_detector` (KfsGridDetectorNode)
> 源文件: `zone_detection/kfs_grid/detector_node.py`, `config.py`, `color_scorer.py`, `qt_window.py`
> 原始脚本: `script/kfs_grid_qt.py`
> 目标: 等待 zone3 TF 锁定后, 统计九宫格 9 个格子内红/蓝色点云净胜分, 实时分类并发布 Marker 可视化

---

## 1. 概述

九宫格是 3×3 排列的 3 层高台方块，每个方块表面涂有红色或蓝色。KFS Grid 节点在 zone3_localizer 锁定九宫格 TF 后，对每个格子独立统计点云颜色，用**色彩纯度权重算法**判定该格属于红方/蓝方/空格/不确定，并将结果通过 MarkerArray 实时显示在 RViz 中。

核心挑战：
- 光照变化导致 RGB 绝对值漂移，HSV 硬阈值不可靠
- 亚克力边框反光（青色）容易误判为蓝色
- 需要区分"空格"（方块的物理空洞）和"不确定"（有颜色但不够鲜明）

## 2. 完整处理流程

### 2.1 流程总览

```
/odin1/cloud_slam (含 RGB)
    │
    ▼
┌─ 2.2 解析点云 (x/y/z/r/g/b) ────────────────────────┐
│  从 PointCloud2 提取 6 通道                           │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.3 查询 zone3 TF ───────────────────────────────┐
│  odom → {blue|red}_zone3_root                      │
│  未就绪 → 跳过本帧, is_locked=False                 │
└───────────────────────────────────────────────────────┘
    │ 就绪
    ▼
┌─ 2.4 点云坐标系变换 ─────────────────────────────┐
│  source_frame → odom (全旋转矩阵)                    │
│  to_height_frame: Z 投影到 odom Z 轴                │
│  GroundEstimator: 获取 ground_z                      │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.5 计算 grid_center + 投影到 grid-local ────────┐
│  grid_center = zone3_root + 固定偏移 (场地模型)       │
│  lx = cos*(px-gx) + sin*(py-gy)   # 深度            │
│  ly = -sin*(px-gx) + cos*(py-gy)  # 宽度            │
│  h  = z_h - ground_z               # 离地高度       │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.6 ROI 预筛 ────────────────────────────────────┐
│  |lx|≤2.0, |ly|≤1.08, h∈[0.5, 2.8]               │
│  广域粗筛: 剔除远离九宫格的点                        │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.7 多帧累积 (ACCUMULATE_FRAMES=20) ────────────┐
│  缓存 ROI 内点 (h, lx, ly, r, g, b)                │
│  累积不足 → 继续下帧                                 │
└───────────────────────────────────────────────────────┘
    │ 累积完成
    ▼
┌─ 2.8 🚀 色彩纯度权重矩阵 (向量化) ───────────────┐
│  red_diff  = max(0, R - max(G,B))                   │
│  w_red     = (red_diff / 255) * (R / 255)           │
│  blue_diff = max(0, B - max(R,G))                   │
│  w_blue    = (blue_diff / 255) * (B / 255)          │
│                                                      │
│  差值项: 该通道对次大通道的优势 → 滤除灰/白          │
│  亮度项: 该通道自身亮度 → 减少暗区噪声               │
│  亚克力反光(0,200,200): B-max(R,G)=0 → auto-zero   │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.9 逐格统计 (3层×3列 = 9格) ───────────────────┐
│  每格检测框: |lx|≤0.60, |ly-yc|≤0.27, |h-zc|≤0.27 │
│  red_score  = sum(w_red[in_box])                    │
│  blue_score = sum(w_blue[in_box])                   │
│  total      = count(in_box)                          │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.10 格子分类 ───────────────────────────────────┐
│  EMPTY:   total < 15                                │
│  RED:     red > blue AND red/blue ≥ 1.5             │
│           AND red ≥ max(20, total×3%)               │
│  BLUE:    blue > red AND blue/red ≥ 1.5             │
│           AND blue ≥ max(20, total×3%)              │
│  UNKNOWN: 其他                                       │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.11 全局汇总 ───────────────────────────────────┐
│  统计 9 格中 RED/BLUE/EMPTY/UNKNOWN 各有多少格       │
│  全局主导色: total_red/total_blue ≥ 1.3 → RED/BLUE  │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.12 发布 MarkerArray ───────────────────────────┐
│  9 格 CUBE Marker, 颜色随检测结果变化:              │
│    RED → 亮红, BLUE → 亮蓝, EMPTY → 深灰, UNKNOWN → 浅灰│
│  0.5s 节流发布, Marker 生命周期 1s                  │
└───────────────────────────────────────────────────────┘
    │
    ▼
┌─ 2.13 终端 + CSV 日志 ────────────────────────────┐
│  终端 (2s节流): 帧/ROI/格点数 + R/B分数 + 主导色    │
│  CSV: 逐帧详细记录 confidence/grid/root 全部字段     │
└───────────────────────────────────────────────────────┘
```

### 2.8 色彩纯度权重算法详解

**核心思想**: 不用 HSV 硬阈值判断"红色/蓝色"，而是计算每个点对红/蓝通道的**纯净度贡献**。

**红色权重公式**:
```
w_red = max(0, R - max(G,B)) / 255 * (R / 255)
         \_____ 差值项 _____/     \_ 亮度项 _/
```

| 项 | 作用 | 滤除 |
|----|------|------|
| 差值项 `max(0, R - max(G,B))` | R 对 G,B 的优势 | 灰色(R=G=B)、黄色(R=G>B)、青色(R<G=B) |
| 亮度项 `R/255` | R 通道绝对亮度 | 暗红色噪声 |
| 乘积 | 两条件同时满足 | 仅高纯度+高亮度红色得高分 |

**蓝色同理**, `max(0, B - max(R,G)) / 255 * (B / 255)`.

**亚克力青色自动归零示例**:
```
青色 (0, 200, 200):
  red_diff  = max(0, 0 - max(200,200)) = max(0, -200) = 0 → w_red = 0 ✓
  blue_diff = max(0, 200 - max(0,200)) = max(0, 0) = 0 → w_blue = 0 ✓
→ 自动归零, 完全滤除
```

**与 HSV 硬阈值对比**:

| 方案 | 光照适应 | 青色处理 | 阈值数量 |
|------|---------|---------|---------|
| HSV 硬阈值 | ❌ 绝对值漂移 | 需要额外规则 | 6+ (H/S/V各区间) |
| 纯度权重 | ✅ 基于相对差异 | ✅ 自动归零 | 4 (判定门槛) |

## 7. 生命周期

```
启动 → 等待 zone3 TF 锁定 → 累积 20 帧高位点 → 颜色统计+分类
                                                    │
                                          ┌─────────┴─────────┐
                                          ▼                   ▼
                                    终端输出结果         Marker 更新颜色
                                    (2s 节流)          (0.5s 节流)
                                          │                   │
                                          └─────────┬─────────┘
                                                    │
                                          清空累积 → 重新累积
                                          (持续循环)
```

- **zone3 未锁** → 空转等 TF, is_locked=False
- **累积不足 20 帧** → 每帧缓存，不发统计
- **累积完成** → 统计+发布，清空重新累积
- **Qt 模式** → Qt 窗口 10Hz 读 node.cell_stats/node.cell_results 刷新

## 8. 异常保护

| 保护点 | 位置 | 机制 |
|--------|------|------|
| TF 查询失败 (zone3) | `_resolve_zone3_tf` | 返回 None, 跳过该帧 |
| TF 查询失败 (cloud→odom) | `_cloud_cb` | try/except, 跳过该帧 |
| 地面检测 TF 不可用 | `GroundEstimator.to_height_frame` | 返回 None, 跳过该帧 |
| 点云空数据 | `_cloud_cb` | n_total==0, return |
| RGB 解析失败 | `_parse_rgb` | 返回 None, 跳过该帧 |
| uint8 溢出 | `compute_red_blue_scores` | int16 转换防溢出 |
| `__del__` 半初始化 | `__del__` | hasattr 保护 |
